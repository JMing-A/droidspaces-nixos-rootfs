# 使用指南

本文面向**使用者**：想在自己的 Android 设备上跑 NixOS 容器，只需要下载一个压缩包、导入 Droidspaces，别的不必关心。

想改流水线、加变体、看内部机制，看 [`架构说明.md`](架构说明.md)。

---

## 1. 你需要什么

| 项 | 要求 |
|---|---|
| 设备 | Android，已安装 [Droidspaces](https://github.com/ravindu644/Droidspaces-OSS) |
| 架构 | `aarch64`（绝大多数手机）或 `x86_64`（模拟器、部分平板/PC 版 Android） |
| 内核 | 5.10 及以上（NixOS 变体依赖较新的 cgroup / namespace 特性） |
| 空间 | 压缩包大小 × 2.5 左右（解压后更大） |
| root | 按 Droidspaces 的要求，需要具备运行容器的权限环境 |

包里的 systemd 与内核耦合较强，**内核版本过低会启动失败**，不是包坏了。

## 2. 下载压缩包

### 2.1 方式一：从 Release 直接下（推荐）

1. 打开本仓库页面，点右侧 **Releases**。
2. 选最新的 Release（标着 `Latest` 的那个）。
3. 在 **Assets** 里找文件名匹配你架构的条目：

```text
<变体名>-Droidspaces-rootfs-<arch>-<build_date>-<tag>.tar.xz
```

示例：

```text
NixOS-Minimal-Droidspaces-rootfs-aarch64-20261112-v20261112-030000.tar.xz
```

文件名里 `aarch64` 还是 `x86_64` 就是要看的字段，其余部分（变体名、日期、tag）不影响能不能用，只影响内容新旧。

### 2.2 方式二：让 App 读索引

`rootfs.json` 是给 App 用的清单。App 从该地址读取后，会自动列出「适配你设备架构」的条目，点一下就开始下载。

如果 App 支持自定义源，填仓库根目录 `rootfs.json` 的 raw 地址即可：

```text
https://raw.githubusercontent.com/<owner>/<repo>/<默认分支>/rootfs.json
```

### 2.3 方式三：从 Actions artifact 下（临时产物）

如果你自己触发了一次 `publish: false` 的构建，产物在 run 页面的 **Artifacts** 区域：

- 名字形如 `rootfs-aarch64-minimal`；
- **只保留 7 天**，过期即删；
- 下载下来是 zip，解压后才是 `.tar.xz` 和 `SHA256SUMS-*.txt`。

## 3. 校验 SHA256

下载后先校验，能排除「下载中断」和「被中间层篡改/替换」两类问题。

### 3.1 数据来源

| 来源 | 位置 | 可信度 |
|---|---|---|
| `SHA256SUMS-<arch>-<file>.txt` | 同一 Release 的 Assets 里 | 高（与包同批产出） |
| `rootfs.json` 的 `sha256` 字段 | 仓库根目录 `rootfs.json` | 高（同上） |
| Release notes 表格 | 只有大小，没有 sha | 仅用于核对体积 |

`SHA256SUMS` 文件内容是标准 `sha256sum` 格式：

```text
<hash>  <filename>
```

### 3.2 在 Android 上校验

有 Termux 或用 `toybox`/`busybox` 的环境：

```sh
# 把压缩包和 SHA256SUMS 文件放在同一目录
sha256sum -c SHA256SUMS-aarch64-NixOS-Minimal.txt
```

输出 `XXX.tar.xz: OK` 表示通过；`FAILED` 表示文件损坏或被替换，删掉重下。

没有 `sha256sum` 时，先单独算再人工比对：

```sh
sha256sum NixOS-Minimal-Droidspaces-rootfs-aarch64-20261112-v20261112-030000.tar.xz
```

把输出的 64 位十六进制与 `rootfs.json` 里的 `sha256` 或 `SHA256SUMS` 文件里的值比对，**必须完全一致**。

### 3.3 在电脑上校验

Linux / macOS：

```sh
sha256sum -c SHA256SUMS-aarch64-NixOS-Minimal.txt
# macOS 没有 sha256sum 时：
shasum -a 256 -c SHA256SUMS-aarch64-NixOS-Minimal.txt
```

Windows（PowerShell）：

```powershell
Get-FileHash .\NixOS-Minimal-Droidspaces-rootfs-aarch64-20261112-v20261112-030000.tar.xz -Algorithm SHA256
```

把 `Hash` 与清单里的值逐字符比对。

### 3.4 校验不通过怎么办

| 现象 | 处理 |
|---|---|
| 文件大小与 `size_bytes` 不一致 | 下载被截断，重下 |
| sha256 不一致但大小相同 | 下载源有问题（代理、镜像站改包），换官方 Release 直链 |
| `SHA256SUMS` 里的文件名与你下载的文件名不同 | 正常，除非你改过名；`sha256sum -c` 需要文件名完全一致，可以先 `mv` 回去 |

## 4. 导入 Droidspaces

不同版本的 Droidspaces App 界面略有差异，通用流程如下：

1. 把 `.tar.xz` 放到设备上任意可读目录（不需要解压）。
2. 打开 Droidspaces → 新建容器 / 导入 rootfs。
3. 选择「从本地文件导入」，指向该 `.tar.xz`。
4. 等待解压完成（文件较大时可能需要几分钟，**不要中途返回**）。
5. 启动容器，首次启动会比之后慢（systemd 需要初始化状态目录）。

### 4.1 首次启动注意

| 项 | 说明 |
|---|---|
| 容器内 root | 容器内的 `root` 是容器命名空间里的 root，不等于宿主已提权 |
| 网络 | 默认走宿主的网络命名空间；需要独立网络时按 App 提供的选项配置 |
| 时区 / 语言 | 默认 UTC + `C` locale。需要的话在容器内自行设置，或用 Droidspaces 的启动参数 |
| 包管理 | 用 `nix` 装东西，不要找 `apt` / `apk`，NixOS 里没有 |
| 重启保留 | 容器 rootfs 是可写的，但 NixOS 的声明式配置不会因你 `nix` 装了包而永久生效；需要长期保留就写进自己的 flake |

### 4.2 安装软件

```sh
# 临时进入带某软件的环境，不修改系统
nix shell nixpkgs#curl nixpkgs#git

# 或临时安装到当前用户 profile
nix profile install nixpkgs#htop
```

### 4.3 启动失败时先看这个

| 现象 | 常见原因 |
|---|---|
| 卡在 systemd 启动，反复重启 | 宿主内核 < 5.10；或缺少 cgroup v2 |
| `Failed to mount /sys/fs/cgroup` | 容器没有正确的 cgroup 命名空间权限 |
| 启动后没有网络 | 宿主网络未就绪，或 App 未授予网络权限 |
| `Read-only file system` | 导出/挂载方式把 rootfs 设成了只读，检查导入选项 |

以上多数是运行环境问题，不是压缩包本身的问题。换一个变体（例如 `minimal` 而不是 `minimal-tools`）能排除「某个包拖慢/拖崩启动」的可能。

## 5. 只构建某一个变体

如果你想自己跑一次构建（例如官方 Release 还没更新），可以在 Actions 里只构建你需要的那个变体，省时间。

### 5.1 网页操作

1. 仓库 → **Actions** → **Build NixOS rootfs** → **Run workflow**。
2. 填写输入：

| 输入项 | 建议值 | 为什么 |
|---|---|---|
| `variants` | `minimal`（或 `minimal-tools`） | 只跑一个变体，别的变体不构建 |
| `systems` | `aarch64-linux`（手机）或 `x86_64-linux` | 只跑你的架构 |
| `include_experimental` | `false` | 排除实验性变体 |
| `publish` | `true`（想发 Release）或 `false`（只想拿包） | `false` 时产物在 Artifacts，7 天 |
| `tag` | 留空，或自己写 `v20261112-120000` | 留空自动用当前 UTC 时间 |
| `flake_repo` / `flake_ref` | 保持仓库维护者推荐值 | 一般不用改 |

3. 点 **Run workflow**。
4. 等 `build` job 完成。约 10 分钟到 1 小时（有缓存会快很多）。

### 5.2 一次只构建一个变体的取舍

- **优点**：只付一台 runner 的时间，出错时日志短。
- **缺点**：`publish: true` 时 `rootfs.json` 只会包含这次构建的条目（`--allow-partial` 语义），其余条目从索引里消失。需要「完整索引」时应构建 `all`。

### 5.3 用 API 触发

```sh
curl -s -X POST \
  -H "Authorization: Bearer $GH_TOKEN" \
  -H 'Accept: application/vnd.github+json' \
  "https://api.github.com/repos/<owner>/<repo>/actions/workflows/build-nixos-rootfs.yml/dispatches" \
  -d '{
        "ref": "main",
        "inputs": {
          "variants": "minimal",
          "systems": "aarch64-linux",
          "include_experimental": "false",
          "publish": "false"
        }
      }'
```

返回 HTTP 204 即受理。查看结果：

```sh
curl -s -H "Authorization: Bearer $GH_TOKEN" \
  "https://api.github.com/repos/<owner>/<repo>/actions/runs?per_page=3"
```

## 6. 加一个新变体

变体表是数据，加变体**不需要改流水线**，只需要往 `variants.json` 里加一行。

### 6.1 前置条件

flake 里必须已经有对应的输出属性。`attr_path` 的拼法固定为：

```text
legacyPackages.<system>.<output>.<system>.<attr>
```

也就是 flake 里要有：

```nix
legacyPackages.<system>.<output> = {
  <system> = {
    <attr> = <derivation 产出 tar.xz>;
  };
};
```

没有就先在 `flake.nix`（或 `nix/` 下的模块）里加上，再加表。这一点见 [`架构说明.md`](架构说明.md) §7.1。

### 6.2 加一行的步骤

1. 打开 `variants.json`。
2. 在数组末尾追加一个对象（注意逗号）：

```json
  {
    "id": "minimal-tools",
    "name": "NixOS - Minimal Tools",
    "file": "NixOS-Minimal-Tools",
    "distro": "NixOS",
    "description": "Minimal NixOS rootfs plus everyday troubleshooting tools.",
    "output": "nixosRootfsTarballs",
    "attr": "minimal-tools",
    "experimental": false
  }
```

3. 校验表合法性：

```sh
python3 scripts/gen_rootfs_json.py --lint
```

预期输出里能看到新变体，并打印「每个 release 的条目数」。报错说明字段缺失或 `id` / `file` 重复。

4. 提交、推送，然后按 §5 触发一次构建，`variants` 填新 `id`。

### 6.3 字段必须满足的约束

| 约束 | 说明 |
|---|---|
| `id` 唯一 | 重复会 `duplicate variant id` 报错 |
| `file` 唯一 | 重复会 `duplicate variant file` 报错；它决定文件名前缀，撞了会互相覆盖 |
| 七个必填字段 | `id` / `name` / `file` / `distro` / `description` / `output` / `attr`，任何一个为空都报错 |
| `experimental` 是布尔 | 写 `"true"`（字符串）会报错，必须 `true` |
| `id` 里不要有空格或逗号 | `variants` 输入用逗号分隔，含逗号会切不开 |
| `file` 里不要有空格 | 会变成文件名的一部分，也可能让 `sha256sum -c`、Shell 脚本别扭；建议只用字母、数字、`-` |

### 6.4 可选字段

| 字段 | 用途 |
|---|---|
| `experimental` | `true` 时只有 `include_experimental: true` 才构建；默认不写视为 `false` |
| `extra` | 对象，会被原样并入 `rootfs.json` 的条目。例如 `"extra": {"min_kernel": "5.10"}`，App 支持时就能读到 |

### 6.5 新增架构（顺带说明）

只需要在 `systems.json` 加一项：

```json
  "riscv64-linux": { "arch": "riscv64", "runner": "ubuntu-latest" }
```

`arch` 会进文件名，`runner` 直接当 GitHub `runs-on` 用。前提同样是对应 `legacyPackages.<system>` 输出存在，且有可跑的 runner。

## 7. 常见疑问

| 问题 | 答 |
|---|---|
| 压缩包能直接 `tar -xf` 到电脑上用吗 | 它是容器 rootfs，不是完整发行版镜像，解到电脑也不能直接引导 |
| 变体之间能互相升级吗 | 不能。换变体等于换 rootfs，需要新建容器 |
| `minimal` 和 `minimal-tools` 怎么选 | 只跑一两个服务选 `minimal`；需要现场排障（`curl`、`git`、编辑器）选 `minimal-tools` |
| 包里的系统能 `apt` 吗 | 不能，NixOS 用 `nix` 管理软件 |
| 每次 Release 都要重下吗 | 只有需要新版本时才下。旧包只要能启动就可以一直用 |
| App 里看不到新包 | Release 里的 `rootfs.json` 还没更新（发行流程未跑完），或 App 缓存了旧索引，刷新/重进一次 |
| 校验和对不上但我这边网络正常 | 检查是否从镜像站下载；镜像站可能缓存了旧文件或改名，换官方 Release 直链重下 |
